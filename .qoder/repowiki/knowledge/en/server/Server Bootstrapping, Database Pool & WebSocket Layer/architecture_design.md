Three cohesive concerns are co-located in this leaf module:
- `index.ts` is the application entrypoint: it creates an Express app, registers body parsing, mounts every feature route under `/api/*`, conditionally serves the built `public/` SPA with a catch-all fallback to `index.html`, then boots the HTTP server and wires up the WebSocket layer.
- `db.ts` exports a single `mysql2/promise` connection pool configured from `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD`, `DB_NAME` environment variables; it throws at import time if required vars are missing, making DB connectivity a hard dependency of any module that imports it.
- `ws.ts` sets up a `ws` `WebSocketServer` on path `/ws`, authenticates each connection by verifying a JWT token query parameter against `JWT_SECRET`, and tracks clients in two in-memory structures: a `Set<WebSocket>` for admin clients and a `Map<userId, Set<WebSocket>>` for cashier clients. It exposes typed broadcast functions (`broadcastReturnRequest`, `broadcastVoidRequest`, `sendReturnDecision`, `sendVoidDecision`) that push JSON messages only to the appropriate audience.

Dependency direction is one-way: `index.ts` depends on both `db.ts` (for the pool) and `ws.ts` (for `initWebSocket`). Routes in `./routes/*` depend on `db.ts` for queries and on `ws.ts` for broadcasting. The module has no external configuration files — everything is driven by environment variables loaded via `dotenv/config`.
