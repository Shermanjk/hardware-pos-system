Single Express router (`server/routes/returns.ts`) exposes REST endpoints under `/api/returns` — POST `/` (create), GET `/search-approved`, GET `/`, GET `/:id`, PATCH `/:id/approve`, PATCH `/:id/reject`, PATCH `/:id/resolve`. Each handler is guarded by `authenticate` and `requireRole` middleware (Cashier/Admin for creation/query/resolution, Admin-only for approve/reject). Business rules are delegated to `validateReturnItems` in `server/utils/validateReturn.ts`, which validates sale existence, 7-day return window, item eligibility, duplicate in-progress returns, and quantity limits. Return numbers are generated through a shared concurrency-safe sequence from `server/utils/invoiceNumber.js` re-exported as `generateReturnNumber`. All state-changing endpoints use explicit MySQL transactions via `pool.getConnection()` with try/catch/finally ensuring rollback on error and connection release. Side effects include audit logging (`logAuditEvent`), activity logs, inventory adjustments, and real-time WebSocket notifications (`broadcastReturnRequest`, `sendReturnDecision`).
